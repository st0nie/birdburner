DS18B20: DATA GPIO23, VDD on **GPIO22** (adapter power-cycled by firmware), GND common; OLED on 3V3 I2C (SDA GPIO6 / SCL GPIO7). Adapter has 4.7k pull-up; 2 m cable; DATA series 100 ohm, probe-end 0.1 uF(+10 uF) VDD-GND, shield grounded at ESP32 end only; cable 10–15 cm from mains (README "DS18B20 wiring and probe power reset"). Recovery: `src/ds18b20.rs` `Ds18b20::new(data_flex, vdd_output)` with power_off (DATA low first)/power_on/release_data; `src/sensor_recovery.rs` ladder — 5 s without valid read → VDD off 1 s/3 s/10 s each +6 s wait; all fail (~32 s) → `sensor_error`, then 3 s power cycle every 60 s. NEW: heater keeps running during short recovery — `HeaterControl::sensor_resetting()` holds last PID output and preserves PWM phase/integral while already running (standby/stopped/faulted stay off); `SENSOR_RESET_MAX_AGE_MS=45000` ages last valid control sample (attempts don't renew it); real failure, age timeout, manual Stop, fresh overtemp still cut heat. After first good raw read API `sensor:"recovering"` until next valid 5 s average; successful running recovery skips 3-window restart; failed faults still need 3 consecutive good windows. OLED `Sensor reset n/3`; metrics `sensor_resetting`, `sensor_power_cycles_total`, `sensor_recoveries_total`, `birdburner_heater_output_held`. Counters/RST-vs-unplug don't prove CMOS latch-up cause; power cycle is the evidence-backed mitigation. If VCC left on 3V3 firmware works but resets can't help; `src/bin/ds18b20_serial.rs` also powers probe from GPIO22. PID gains editable via industrial `src/index.html` form → POST `/api/pid {kp,ki,kd}` (all 3 required, finite; Kp 0..100, Ki 0..2, Kd 0..200, rounded 0.001); persisted as u32 thousandths in Settings BDS4 36-byte record (gains at 20/24/28, CRC at 32); BDS1/2/3 migrate to defaults 10/0.1/0; flash dual sectors 0xFF0000/0xFF1000, RST/unplug retain saves; `settings_pending` true until read-back verification, failures retry; frontend panel confirms flash (not RAM apply), success feedback 4 s. Tests: `node --test tests/frontend.test.mjs`; host picoserve loopback `tests/host/http_tests.rs`. no_std: no float round/floor — bounded non-negative +0.5-and-cast. Prometheus gauges `birdburner_pid_kp/ki/kd` (no rate()); control via Home Assistant or any IoT platform fine; MVP = phone target 15–30 °C + OLED. Demo outside repo at `/tmp/birdburner-hmi-demo`; on-hardware GPIO/flash/thermal verification still pending (user flashes themselves; README "Checking the wiring after the change" pull-VCC/pull-DATA tests).
