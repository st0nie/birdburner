DS18B20: DATA GPIO23, VDD on **GPIO22** (adapter power-cycled by firmware), GND common; OLED on 3V3 I2C (SDA GPIO6 / SCL GPIO7). Adapter has 4.7k pull-up; 2 m cable; DATA series 100 ohm, probe-end 0.1 uF(+10 uF) VDD-GND, shield grounded at ESP32 end only; cable 10–15 cm from mains (README "DS18B20 wiring and probe power reset"). Recovery: `src/ds18b20.rs` `Ds18b20::new(data_flex, vdd_output)` with power_off (DATA low first)/power_on/release_data; `src/sensor_recovery.rs` ladder — 5 s without valid read → VDD off 1 s/3 s/10 s each +6 s wait; all fail (~32 s) → `sensor_error`, then 3 s power cycle every 60 s. Heater keeps running during short recovery — `HeaterControl::sensor_resetting()` holds last PID output and preserves PWM phase/integral while already running (standby/stopped/faulted stay off); `SENSOR_RESET_MAX_AGE_MS=45000` ages last valid control sample (attempts don't renew it); real failure, age timeout, manual Stop, fresh overtemp still cut heat. After first good raw read API `sensor:"recovering"` until next valid 5 s average; successful running recovery skips 3-window restart; failed faults still need 3 consecutive good windows. OLED `Sensor reset n/3`; metrics `sensor_resetting`, `sensor_power_cycles_total`, `sensor_recoveries_total`, `birdburner_heater_output_held`. Counters/RST-vs-unplug don't prove CMOS latch-up cause; power cycle is the evidence-backed mitigation. If VCC left on 3V3 firmware works but resets can't help; `src/bin/ds18b20_serial.rs` also powers probe from GPIO22. PID gains + D-filter low-pass (alpha = dt/(Tf+dt), Tf=0 off) editable via industrial `src/index.html` form → POST `/api/pid {kp,ki,kd}` + optional `d_filter_s` 0–300 s (422 `d_filter_must_be_0_to_300_s`); all 3 gains required, finite; Kp 0..100, Ki 0..2, Kd 0..200, rounded 0.001. Factory gains changed to Kp 20 / Ki 0.02 / Kd 120, default Tf 30 s (`DEFAULT_D_FILTER_MILLI`, `D_FILTER_RANGE_MILLI` in src/heater_control.rs; from 2026-10-09 Grafana data: ~15% duty holds ~0.5 C above ambient, 1–3 min lag, 0.0625 C LSB). Persisted as u32 thousandths in Settings flash dual sectors 0xFF0000/0xFF1000; BDS5 RECORD_LEN 40 — gains at 20/24/28, Tf at 32, CRC at 36; BDS4 keeps gains + default Tf; BDS1/2/3 migrate to defaults 10/0.1/0; RST/unplug retain saves; `settings_pending` true until read-back verification, failures retry; frontend panel confirms flash (not RAM apply), success feedback 4 s. Status `pid_d_filter_s`; Prometheus gauges `birdburner_pid_kp/ki/kd`, `birdburner_pid_d_filter_seconds` (no rate()); control via Home Assistant or any IoT platform fine; MVP = phone target 15–30 °C + OLED. Tests: `node --test tests/frontend.test.mjs`; host picoserve loopback `tests/host/http_tests.rs`; heater_control behaviour tests use `legacy()` config (10/0.1/0) not defaults. no_std: no float round/floor — bounded non-negative +0.5-and-cast.
